### 翻译质量（必须诚实对待）

OPUS-MT 水平：`披针`（pins）、`坦佩尔事件`（Tamper）、`备份登记器`（backup registers）这类错误确实会出现；数值、单位、寄存器名在占位保护下基本可靠。界面已标注"机器翻译"，输出侧有少量术语校正，但**没有做 20 段人工评分**，不能声称质量合格。

## 怎么在本机启动

```powershell
# Node 24（本机可用 codex 自带运行时）
$env:Path="C:\Users\32700\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin;$env:Path"
cd D:\tool\芯片手册翻译器
node node_modules\next\dist\bin\next dev --hostname 127.0.0.1 --port 3010
```

- 不要用 `npm run dev`：fork + IPC 在受限环境会 `spawn EPERM`。
- 翻译运行时已解包在 `.runtime/`（CTranslate2 4.9.0 + SentencePiece 0.2.3，未改全局 Python）。
- 模型已解包在 `models/argos-en-zh/`（含 `install.json` 与包内 README 许可文本）。
- 重装运行时：`powershell -ExecutionPolicy Bypass -File tools\setup-runtime.ps1`
- 重装模型：应用右上角「安装模型」选择 `.argosmodel` 文件；或 `POST /api/model`（multipart `file`）。

## 必须记住的坑

1. **非 ASCII 绝对路径**：CTranslate2 / SentencePiece 用 C++ `std::ifstream`，Windows 下打不开含中文的绝对路径 → `runtime/translate_server.py` 先 `chdir` 到模型父目录再传相对路径。换目录名（仍是中文）时要复查。
2. **管道**：受限环境下 Node 用 `stdio: 'pipe'` 派生子进程会 `EPERM`；翻译服务用 `stdio: 'ignore'` + 本机 HTTP，Next 则必须在放宽权限后启动。
3. **PDF.js 样式**：`PdfReader.tsx` 必须 `import "pdfjs-dist/web/pdf_viewer.css"`，否则文字层不绝对定位、页面错位。
4. **占位符格式**：`[[Zn]]` 实测被模型改写的概率最低；`⟦⟧`（U+27E6/27E7）会被译成 `Q`。
5. **模型下载**：境外源单连接约 20–60 KiB/s，用 `tools/pget.mjs` 多连接可到 250–300 KiB/s；ST 官网 PDF 反而很快。
