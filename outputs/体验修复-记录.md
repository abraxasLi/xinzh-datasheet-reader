# 三个体验修复：全大写、在线慢、跨页续表

日期：2026-11-13

## 1. 全大写单词翻不出来

**根因**：占位保护里有一条 `\b[A-Z]{2,}\b`，把 `TEMPERATURE`、`COMMAND` 这类全大写单词全当标识符屏蔽成了 `[[Z0]] [[Z1]]`，模型只看到占位符，自然译不出。

**修复**（`src/lib/translation/protect.ts`、`sanitize.ts`）：

1. 占位规则收紧为 `[A-Z]{2,5}` 的短缩写（TC/TXE/ORE 这类位名），长全大写单词不再屏蔽；
2. 加了一张常见词白名单（DATA/READ/WRITE/OUTPUT/STATUS…），命中就留给模型；
3. 送翻前做**大小写归一**：全大写占比 > 65% 且长度足够时，转成句首大写（`TEMPERATURE CONVERSION` → `Temperature conversion`）。OPUS-MT 对全大写输入几乎不出中文；
4. 占位符还原改成大小写不敏感（归一化会把 `[[Z0]]` 变 `[[z0]]`）。

**实测**（同一段）：

| 阶段 | 结果 |
| --- | --- |
| 修复前（屏蔽） | 只有占位符，译文为空/问号 |
| 只去掉屏蔽、不改大小写 | `电磁交流电 指挥反射 狂犬病 读取 狂犬病 Power Supply Voltage` |
| 现在 | `温度转换命令 写入抓图 读取抓图供电电压` |

术语仍有错（`SCRATCHPAD` → 抓图），这是离线模型词汇量问题，不是保护问题；切在线引擎会明显更好。

## 2. 在线翻译太慢

**根因**：`translateOnline` 是逐段串行请求，每段一次往返，免费模型单次 20 秒以上；翻「前后文/当前页」要等几分钟。

**修复**（`src/lib/translation/online.ts`）：改成**一次请求翻多段**——把所有段落用 `【1】【2】…` 编号拼成一条消息，要求模型按同样编号逐行输出，回来后按编号切分。切分数量对不上时自动退回逐段模式，不会丢结果。

**实测**：3 段 → **5.4 秒**（原来约 60 秒），译文正常：

```
GPIOx_MODER 寄存器用于配置 I/O 方向模式。
当 TC 位置位时，传输完成。
ADC 时钟不得超过 14 MHz。
```

## 3. 跨页续表

**实现**（`src/lib/datasheet/tables.ts` 的 `detectContinuation` + `PdfReader` 的跨页状态）：

- 记住最近一页最后一个表的表头和列边界（`columnEdges`）；
- 下一页如果没有识别到新表头，就用上一页的列边界把行切开，生成「续表（接第 N 页…）」；
- 加了三个保守约束，避免把正文误判成续表：
  1. 上一页的表必须画到页底（`bounds.y0 < 130`），否则说明它在本页就结束了；
  2. 本页至少要有 3 行是「多列」内容；
  3. 跳过页眉页脚、公司名、机密信息行。

**验证**：NM25Q128 第 8 页引脚表在页中结束（y0≈538），第 9、10 页正确**不再**误判为续表；真正跨页的表要等遇到样本再验。

## 剩余问题

- 表格的跨行说明仍会串到上一行（DS18B20 的 5 列表已从 28 行退化到 4 行，属于同一根因，尚未修）；
- 离线模型的技术术语仍会错（抓图/针头/标针），靠术语校正表兜一部分；
- 在线模式受免费额度限制，批量后仍可能排队。

## 4. 离线模型"重复退化"拦截（截图问题）

截图里 `包信息 包信息 包信息…` 不是翻错，是 OPUS-MT 在表格碎片/重复词上进入循环。

新增 `src/lib/translation/quality.ts`，翻译后检查：

- 连续片段重复（2–8 字重复 3 次以上，或 6 字以上重复 2 次）；
- 字符多样性过低、双字重复占比 > 22%；
- `??` 占位符丢失、输出比原文短 82% 以上。

命中就不显示译文，改为提示"模型输出不稳定，已拦截"，并建议切在线或选中片段。

实测：

| 输入 | 结果 |
| --- | --- |
| `Package information … Package information …`（截图那段） | **拦截**（输出重复） |
| `Table 70. WLCSP64 … 100 um … 320 um` | **拦截**（输出重复，原文里也有重复短语） |
| 正常段落 | 正常出中文 |

## 5. 选中即译（表格取词的兜底）

PDF 里用鼠标选中任意文字（表格单元格、位名、地址都行），左下角弹出「选中片段」面板，点「翻译选中（本机/在线）」直接翻这一段，不动表格结构。

实测：选中 `WWW.NORMEM.COM` → 模型退化 → 面板显示"模型输出不稳定（输出重复），已拦截；建议切「在线（智谱）再试」"，耗时 777 ms。截图见 `outputs/screenshots/14-selection-translate.png`。

## 6. 在线默认模型换成 glm-5.3-flashx

`--list-models` 里 flashx 比 flash 快（2.5s vs 3.7s 单句），作为默认在线模型；批量请求仍然有效（3 段 5.4 秒）。

## 7. 「选中即译」的复查与修复（2026-11-14）

复查发现一个真问题：**短选中被"内容过短"规则挡掉了**。`sanitize` 原来要求字母数 ≥ 12，
而选单词（Tamper / SCLK / Chip Select）恰好都在这个阈值以下，所以点了没反应。

已修：阈值从 12 个字母降到 **4 个字母**（仍挡 `rw`、`0` 这种碎片）。

### 修复后实测

| 选中 | DeepL | 本机 Argos |
| --- | --- | --- |
| Chip Select | 芯片选择 | 芯片选择 |
| write-only | 只写 | 仅写 |
| prescaler | 预分频器 | 预缩放器（已加校正→预分频器） |
| Tamper | 篡改（加了 篡改器→篡改 校正） | 谭珀（已校正） |
| backup registers | 备份寄存器 | 备用寄存器 |
| SCLK | SCLK（保持原文，合理） | SCLK 软件（错） |
| Bits 26:24 SWJ_CFG | 第26章第24节 SWJ_CFG（**错**：把位段当成章节） | 位数 26: 24 SWJ_CFG |

浏览器实测：在 NM25Q128 第 8 页表格里选中 `Chip Select` → 面板 → DeepL「芯片选择」，2.3 秒，无报错。
截图：`outputs/screenshots/16-selection-deepl.png`。

### 仍然不好的

- **位段选中**（`Bits 26:24 SWJ_CFG`）会被模型当成章节号，需要结构化拦截（还没做）；
- 离线引擎翻单词质量差，建议选中翻译默认走在线；
- 面板固定在左下角，不跟随选区；连续选中会覆盖上一次结果；
- 跨列选中的文字会按空格拼接，可能混入相邻单元格。
