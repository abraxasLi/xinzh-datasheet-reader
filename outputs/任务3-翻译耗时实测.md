## 如何读这些数字

- 客户端总耗时：发起本地 HTTP 请求至收到 JSON，包括本地开发框架开销；第一段也可能含首次编译开销。不是浏览器实际绘制完成时间。
- API 内总耗时：进入 POST 至响应对象生成，包含预处理、保护、引擎调用和结果处理。
- 调 GLM/DeepL：接口等待对应 provider 函数的耗时，包含网络、服务排队、生成及现有重试。外部 API 不提供纯模型推理时间，不能把这里称为纯推理时间。
- 0 表示没有调用另一个引擎，不表示另一个引擎瞬间完成。
- 每段对每个引擎仅测一次；样本量小，网络和免费服务排队都会波动，不能据此承诺稳定延迟。

## 串行、并行与批量

本次脚本明确依次 await 10 个请求，每次一段；未并行、未额外重试。GLM 和 DeepL 互不串接，一次翻译只选一个 provider。

代码检查：GLM 多段先合成一次编号批量请求，段数不匹配或批量失败后，才用 for/await 逐段串行回退。DeepL 多段使用 text 数组一次请求，属于批量而非多个并行请求。两者现有网络重试等待分别为 6000 ms 和 4000 ms，最多重试一次；本次未观察到导致失败的情况，多段回退未进行实测。原有批量 items.ms 是整批耗时均摊，不是每段独立推理计时，本表每次一段因此不存在均摊歧义。

主要耗时来自在线调用；本轮只量时间，不做提速调整。
